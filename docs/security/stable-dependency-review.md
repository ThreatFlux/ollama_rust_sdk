Both stopped containers were exported for package/file/ELF inspection. See [captured evidence](original-image-evidence.txt).

The CA supplier record is old `20250419`; replacement trust data and metadata are refreshed together, without assuming a later fixed bundle proves this original artifact safe.

## Primary evidence and implemented remediation

Debian tracker pages linked per row were fetched for this review; source-package ranges require the target/component distinctions above. [GCC aligned-new fix](https://github.com/gcc-mirror/gcc/commit/200183d4ab5d57575f3dfebc6af3baf649910b9e) explicitly excludes the posix_memalign implementation; [PBDS fix](https://github.com/gcc-mirror/gcc/commit/aaa8351f4d2e636f9680a1f0a8ebc2f0a60611e6) changes the template header. [zlib CRC fix](https://github.com/madler/zlib/commit/ba829a458576d1ff0f26fc7230c6de816d1f6a77) adds negative-length checks. [zlib writer discussion](https://github.com/madler/zlib/issues/1310) still leaves the Debian1.3.1 affected-range disagreement unresolved. Debian's minor/no-DSA or upstream-disputed dispositions are not treated as fixed packages.

The replacement Dockerfile builds all features using current stable Rust 1.99.1 and Alpine's maintained musl, explicitly disabling Rust's older bundled libc using `link-self-contained=no`. It verifies static PIE, no interpreter/shared dependencies in both app and tini, and records the actual libc archive selected by the linker. The final distroless/static runtime contains no glibc, GCC shared runtimes, or libz. This preserves the Ollama HTTP/streaming CLI functionality; this SDK needs no native binary-analysis libraries. Embedded musl and Rust/native dependencies remain part of ongoing provenance/security maintenance.

A maintained Debian trust-store stage copies the real fixed CA bundle AND its exact supplier package record, requiring at least `20250419+deb13u1`. No relabel-only metadata fix is used. The trust-store update follows [Debian DSA-6572](https://www.debian.org/security/2026/dsa-6572).

Validation requires repository full local CI, original-vs-replacement ELF/package checks, real CLI requests to a local HTTPS Ollama fixture with trusted success and untrusted/hostname rejection, and current all-severity Trivy scans for each built architecture. Validation results and any remaining platform limitations are recorded in the pull request. TPs and the undetermined writer finding remain visible until a replacement scan resolves them; no SARIF deletion or global ignore is justified. Historical immutable images remain historical artifacts and should not be advertised as remediated simply because a new source revision exists.

The ten scoped FPs above were individually dismissed through the GitHub API with original-artifact reasons on 2026-10-21. The 20 TP package findings and one undetermined zlib finding remain open. Original CA bundle inspection additionally confirmed both distrusted subjects still present (both platform bundle SHA256 `714d457d580922dbf1d0be8bd35ba236a842b50b0072ae791582a19adef772a5`); the trust-store stage fixes this real historical trust issue as well, rather than dismissing it using a replacement bundle.

Validation completed locally: the full `make ci-local` gate, including strict linting, all-feature/no-default/powerset tests, documentation contracts and the unchanged Rust 1.97.1 MSRV, passed. The ARM64 complete image passes static/native/CA provenance checks and a real CLI HTTPS `/api/tags` fixture: trusted success, unknown issuer rejection, and hostname rejection. Trivy 0.76.0 with the current database reports zero OS and Cargo vulnerabilities across all severities. AMD64 validation is recorded in the PR when completed.

Hosted container validation now runs natively for AMD64 and ARM64, including both the real HTTPS fixture and all-severity scans. AMD64 explicitly preserves the original `.github/workflows/docker.yml:scan` analysis key/category and empty matrix. ARM64 uploads independently so a clean result on one platform cannot replace the other's findings. The manual key is supported by the pinned [CodeQL environment contract](https://github.com/github/codeql-action/blob/v4.39.0/src/environment.ts) and [getAnalysisKey implementation](https://github.com/github/codeql-action/blob/v4.39.0/src/api-client.ts). Verify hosted analysis identity after the first upload; no historical analysis is deleted.
